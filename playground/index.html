Flujo listo para ejecutar

  1. 01

    Pedir token

    Primera llamada: cambia credenciales por un access_token de 15 min.

    POST/oauth/tokenmock vivo
    Request body
    grant_type=client_credentials&client_id=CLI-DEMO-01&client_secret=<client_secret>
    Response
    Pulsa «Ejecutar →» para disparar la petición.
  2. 02

    Descubrir mi partnerId

    Trae los scopes, límites y qué negocios tengo abiertos.

    GET/partner/v1/memock vivo
  3. 03

    Registrar webhook

    Dejar la URL donde van a llegar los avisos del PIM.

    POST/partner/v1/webhooksmock vivo
    Request body
    {
  "url": "https://{host-del-seller}/avisos-pim",
  "events": [
    "proposal.received",
    "proposal.accepted",
    "product.sku_created",
    "product.published"
  ]
}
    Response
    Pulsa «Ejecutar →» para disparar la petición.
  4. 04

    Descubrir categoría

    La IA sugiere a qué categoría pertenece el producto a partir del título.

    GET/partner/v1/categories/discovery?business=MKP&q=bateria portatil 20000 mAhmock vivo
  5. 05

    Validar la ficha

    Prueba la ficha SIN crearla. Captura errores antes del alta real.

    POST/partner/v1/validationsmock vivo
    Request body
    {
  "business": "MKP",
  "items": [
    {
      "externalRef": "DEMO-PB20",
      "categoryId": "CAT-DEMO-0412",
      "title": "PB-DEMO-20 Marca Demo"
    }
  ]
}
    Response
    Pulsa «Ejecutar →» para disparar la petición.
  6. 06

    Crear propuesta

    La llamada que cataloga. Responde 201 con proposalId y estado IN_APPROVAL.

    POST/partner/v1/proposalsmock vivo
    Request body
    {
  "business": "MKP",
  "externalRef": "DEMO-PB20",
  "categoryId": "CAT-DEMO-0412"
}
    Response
    Pulsa «Ejecutar →» para disparar la petición.
  7. 07

    Consultar propuesta

    Después del aviso product.published, consulto el estado final.

    GET/partner/v1/proposals/PROP-000123mock vivo

Avisos (webhooks)

Después de POST /proposals o POST /batches, el PIM manda avisos firmados con HMAC-SHA256 al webhook del seller. Aquí los simulamos con delays reales.

  • Aún no hay avisos. Ejecuta el paso que crea la propuesta / lote para que empiecen a llegar.
Dev kit · importar en Postman

Tres puertas para arrancar en 30 segundos.

El mock responde con los JSON del §4 del contrato. Importas la colección, cambias el baseUrl al mock y le das Send.

1 · URL del mock

Base para /partner/v1/* y /oauth/token.

https://75d6e481-577f-4f80-9431-f734b175ab8c.mock.pstmn.io

Health-check: GET /partner/v1/me → partnerId: SELLER-DEMO-01.

2 · Colección Postman

37 requests + 37 ejemplos, variables ligadas (proposalId,batchId, categoryId…).

⤓ Descargar JSON (v2.1.0)

Impórtala en Postman, Insomnia o Hoppscotch y cambia baseUrl por el URL del mock.

3 · cURL de arranque

Para pegar directo en una terminal.

curl https://75d6e481-577f-4f80-9431-f734b175ab8c.mock.pstmn.io/partner/v1/me \
  -H "Authorization: Bearer eyJ...ejemplo"

El mock devuelve siempre el payload de ejemplo — es sandbox de contrato, no una API con estado.
